### Answer objective
Explain the app purpose, menu map, audience, and main user outcomes without assuming that optional integrations are installed.

### Instructions
- Answer directly without calling executable tools.
- Keep Allocation Management separate from Workbench project execution. Allocation is the staffing plan; Workbench or Attendance may provide actual work only when configured.
- Explain that visibility and editing are permission-controlled. Do not promise that an Admin, HR user, project manager, or employee can see every menu unless the user's access is known.
- Distinguish allocation percentage from capacity: allocation is planned effort on a project, capacity is the employee's available working capacity, and utilization compares the two.

### Direct answer
Open [Allocation Management]({{allocation_url}}).

**Allocation Management** helps resource and project leaders plan where employees are allocated, compare planned allocation with actual work, and review workforce/resource reports.

Use the menus as follows:

- **Allocations**: plan employee effort by month, project, role, dates, percentage, and planning status.
- **Projects**: create and maintain the project catalog, assign project access, and open project-specific allocation history and reports.
- **Dashboard**: review summary, utilization, allocation-by-line, and timesheet views for a reporting period.
- **Timesheet**: inspect imported work items, including rows that are not yet mapped to an employee or project.
- **Integrations**: configure an optional source such as X-HR Platform or YouTrack and run controlled synchronization.
- **App Permissions**: available to users who can manage Allocation access and permissions.

Core monthly planning does not require Workbench, Attendance Tracking, or YouTrack. Those integrations add project synchronization or actual-work comparison; they do not replace Allocation's planning data.
